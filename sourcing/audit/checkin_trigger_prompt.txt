CHECK-IN on the Quotables sourcing wave. Run `python3 sourcing/orchestrate/mark_dispatched.py status`. For each in-flight batch call get_session; for any session that is idle/completed, find its `Quotables results batch_NNNN` artifact (Artifact list), read it, save the raw HTML to a file, and ingest with `sourcing/orchestrate/handle_result.sh batch_NNNN <file>`, then `mark_dispatched.py archived <session>`. For any session killed by a usage limit or errored: ingest whatever partial page exists the same way, build a remainder batch (batch_NNNNb.tsv with the header line and the rows not yet in sourcing/web_results/batch_NNNN.jsonl), `mark_dispatched.py failed batch_NNNN <session> "<reason>"`, and re-dispatch. Keep 8 sessions in flight by dispatching the next batches with prompts from `python3 sourcing/orchestrate/make_sibling_prompt.py sourcing/batches/batch_NNNN.tsv batch_NNNN session_018SonTZr2inCLhXqzcif71w` (create_session, permission_mode auto, tag quotables-sourcing) and `mark_dispatched.py dispatched batch_NNNN <session>`. Run `sourcing/orchestrate/commit_progress.sh "<message>"` after every ingest and after recording dispatches (commits as alvations; push will 403 until the GitHub app is installed, keep retrying). Every ~10 batches refresh the bundle with `bash <scratchpad>/make_bundle.sh` and send it with SendUserFile. Finally re-arm this check-in with create_trigger for 45 minutes later (same prompt, initiation own_followup).
